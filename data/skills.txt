# Was wird wann freigeschaltet.
# ==============================
#
# Diese Datei bestimmt den ganzen Skilltree. Das Spiel liest sie beim Start.
# Ändern, Spiel neu starten - fertig. Neu bauen musst du dafür nicht.
#
# Der Baum wird NICHT vorher gewürfelt. Du siehst immer nur einen Schritt
# weiter. Erst wenn du etwas kaufst, wird gewürfelt, was dahinter kommt - aus
# allem, was zu diesem Schritt passt UND was du schon hast.
#
#
# EINE ZEILE PRO PUNKT
#
#     schlüssel     schritt   preis   wie oft      [braucht ...]
#
#   schlüssel   was der Punkt freischaltet. Die Liste steht unten.
#   schritt     ab wann bis wann er auftauchen darf.
#               "4" heißt genau Schritt 4, "3-8" heißt irgendwo dazwischen,
#               "3-" heißt ab Schritt 3 ohne Ende.
#   preis       Grundpreis in Schritt 1. Weiter draußen wird alles teurer,
#               siehe "steigerung". Der Grundpreis macht nur noch den
#               Unterschied INNERHALB eines Schrittes aus.
#   wachstum N  optional, nur bei "oft": womit das Gewicht pro Schritt nach
#               außen malgenommen wird. 1.2 heißt, der Punkt wird weiter
#               draußen immer häufiger - so werden die "+1"-Punkte spät zum
#               Normalfall, während neue Befehle seltener werden.
#
#   wie oft     "einmal"  = gibt es im ganzen Baum nur ein einziges Mal.
#                           Dahinter darf eine Zahl stehen: wie stark der
#                           Punkt gezogen wird (ohne Zahl: 2).
#               "oft N"   = darf immer wieder kommen, N ist das Gewicht.
#                           Je größer N, desto öfter.
#   braucht X   der Punkt taucht erst auf, wenn X GEKAUFT ist.
#               Damit gibt es "+1 Bedingung" erst, wenn du "if" hast.
#
# Alles hinter einem # ist Kommentar, leere Zeilen sind egal.
# Umlaute darfst du weglassen: "pruefen" geht genauso wie "prüfen".
#
# WICHTIG: Schritt heißt Tiefe im Baum. Ein Punkt in Schritt 5 hängt hinter
# vier anderen - früher als beim 5. Kauf kannst du ihn also nie haben.
#
# Bei "einmal" wird die Chance nach hinten raus immer größer: am Anfang
# seines Bereichs ist der Punkt selten, am Ende fast sicher. Und läuft der
# Bereich ganz ab, wird er beim letzten Schritt erzwungen. Verlieren kannst
# du also nichts.
#
#
# DIE SCHLÜSSEL
#
#   while         while und do, dazu die erste Schleife
#   for           for, dazu eine weitere Schleife
#   if            if, dazu die erste Bedingung
#   else          else
#   print         print(...)
#   prüfen        block.isThere(), isLoading(), exists(), isGone()
#   geteilt       shared["name"] - übersteht einen Neustart
#   abbauen       block.mine() - abbauen lassen statt selbst klicken
#   verkaufen     item.sell() - die Tasche zu Geld machen
#   tasche        item.has("Stein") - nachschauen, was in der Tasche ist
#   variablen     eigene Variablen (int, float, ...), dazu die erste
#   klassen       struct und class, dazu die erste
#   funktionen    eigene Funktionen und Methoden, dazu die erste
#
#   waschen       item.wash("Stein")   - verarbeiten
#   reinigen      item.clean("Stein")
#   pressen       item.press("Kohle")
#   schmelzen     item.smelt("Kupfer")
#   giessen       item.cast("Kupfer")
#   härten        item.harden("Eisen")
#   polieren      item.polish("Diamant")
#   veredeln      item.refine("Gold")
#
#   legieren      item.alloy("Elektrum") und item.canAlloy("Elektrum")
#                 - zwei Erze zu einem neuen Stoff verschmelzen
#
#   Was von welchem Zustand aus geht, steht in data/verarbeitung.json - das
#   ist ein Netz, keine feste Kette. Der Skilltree sagt nur, welche Schritte
#   du überhaupt benutzen darfst. Welche Legierungen es gibt, steht in
#   data/legierungen.json.
#
#   schleife+     eine Schleife mehr erlaubt
#   bedingung+    eine Bedingung mehr erlaubt
#   variable+     eine Variable mehr erlaubt
#   klasse+       eine Klasse mehr erlaubt
#   funktion+     eine Funktion mehr erlaubt
#   konsole+      eine Konsole mehr
#
#   tempo         +0,5 Zeilen pro Sekunde
#   geld          +1 Geld pro Block
#   nachwachsen   der Block wächst 8% schneller nach


# So viele Schritte hat der Baum. 0 = kein Ende, er waechst immer weiter.
schritte    0

# Je weiter weg, desto teurer: jeder Schritt kostet das 1,5-fache.
# Deshalb macht man erst alles in der Nähe und arbeitet sich dann nach außen.
steigerung  1.7

# So viele neue Punkte macht ein Kauf auf (kleinste und größte Zahl).
kinder      1 3

# So viele Punkte stehen höchstens gleichzeitig offen. Sind schon so viele
# offen, macht ein Kauf nur noch genau einen neuen auf.
offen       10

# Mindestabstand zwischen zwei "einmal"-Punkten, gezählt in Punkten.
# So viele andere Punkte müssen dazwischen liegen. Damit schaltest du erst
# eine Sache frei, spielst ein Stück weiter, und erst dann kommt die nächste -
# statt drei Stück direkt hintereinander.
#
# Punkte mit festem Schritt (z.B. "abbauen 1") halten sich nicht daran: die
# liegen genau dort, wo sie sollen.
abstand     9


# ---- die Sprache ------------------------------------------------------
#
# Alles hier gibt es genau EINMAL. Wenn du es freischaltest, bekommst du
# genau eine Verwendung dazu - mehr nur über die Erweiterungen unten.
#
# Die Bereiche dürfen sich überschneiden - der Abstand oben sorgt dafür,
# dass trotzdem Luft dazwischen bleibt.

abbauen         1        6    einmal 1
verkaufen       2        6    einmal 1
while           3        8    einmal 1
if              4-9     18    einmal 2
variablen       6-11    16    einmal 1
print           7-13    12    einmal 1
tasche          6-11    16    einmal 2   braucht if
prüfen          8-14    14    einmal 1
else           10-16    18    einmal 1   braucht if
for            11-17    20    einmal 1   braucht while
funktionen     12-18    20    einmal 1   braucht variablen

geteilt        15-24    24    einmal 1


# ---- Verarbeiten ------------------------------------------------------
#
# Roh verkaufen bringt wenig. Waschen steht mit Absicht auf einem festen
# Schritt: es kommt damit früh und immer - sonst lohnt sich die Tasche zu
# lange nicht.
#
# Die späteren Schritte bauen aufeinander auf, aber nicht als eine Reihe:
# gießen braucht schmelzen, härten braucht gießen, veredeln braucht polieren.
# Alles andere darf in beliebiger Reihenfolge kommen.

waschen         8-16    10    einmal 2   braucht tasche
schmelzen      10-18    20    einmal 1   braucht waschen
reinigen       12-20    18    einmal 1   braucht waschen
pressen        13-21    22    einmal 1   braucht waschen
giessen        14-22    26    einmal 1   braucht schmelzen
polieren       16-24    28    einmal 1   braucht giessen
haerten        18-26    32    einmal 1   braucht giessen
veredeln       20-32    40    einmal 1   braucht polieren

# Die Verarbeitung ist eine Kette: waschen ist der Anfang, alles andere hängt
# über "braucht" daran. Und waschen selbst braucht "tasche" - also
# item.has(...). Denn erst wenn dein Programm nachschauen kann, was in der
# Tasche liegt, kann es überhaupt entscheiden, WAS es verarbeitet. So bekommst du nie einen Schritt angeboten, dessen
# Vorgänger dir noch fehlt.
#
# Legieren braucht schmelzen: die Zutaten müssen geschmolzen sein, bevor man
# sie zusammenkippen kann (siehe "von" in data/legierungen.json).
legieren       18-28    34    einmal 1   braucht schmelzen


# ---- mehr davon -------------------------------------------------------
#
# Diese Punkte tauchen erst auf, wenn das Passende schon gekauft ist.

schleife+       4-      16    oft 1    wachstum 1.20   braucht while
bedingung+      6-      16    oft 1    wachstum 1.20   braucht if
variable+       8-      12    oft 1    wachstum 1.20   braucht variablen
funktion+      14-      16    oft 1    wachstum 1.22   braucht funktionen
klasse+        16-      18    oft 1    wachstum 1.22   braucht klassen

# Eine weitere Konsole ist ein großer Schritt - deshalb selten.
konsole+        7-      22    oft 1    wachstum 1.10


# ---- Werte ------------------------------------------------------------
#
# Das Brot-und-Butter-Zeug. Hohe Gewichte: davon soll das meiste kommen,

tempo           2-      10    oft 6
